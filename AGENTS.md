# Agent instructions for ci.yml

This repository defines fleet CI policy and implements its repository-local checker, `ci_lint`. Read the policy before changing the README, checker, or a repository workflow. A fleet-wide central scanner that inventories every repository and a scheduler do not exist yet; `ci_lint` itself is implemented and merged, and enforces many rules today against any repository that adopts `ci.toml` schema 3 (opt-in, not automatic). Documentation must distinguish which is which: the "Status" column in `docs/policy-general.md`/`docs/policy-rust.md`/`docs/policy-cpp.md`'s rule tables says, per rule ID, "Enforced by ci-lint (static precheck | runtime | live audit)" or "Candidate."

## Working rules

- Select additional native PR coverage and `ci-full` only for changes to platform implementations (native API/FFI, OS branches, adapters/selectors or native runtime contracts), never merely for callers, shared business logic, helper extraction or unchanged moved OS code. Apply this to repository skills and agent planning/review/integration/landing rules; target inventories do not select coverage. Preserve routine required checks and full release validation. See docs/policy-general.md's "Selecting full PR coverage".

- Preserve required lint, test, platform, and artifact coverage when proposing a faster workflow. Confirm coverage from commands and runs, not from a runner label.
- Represent Python benchmark inputs, results, and reports internally with dataclasses, never raw dictionaries. JSON and Protocol Buffers are allowed at serialization boundaries; type any boundary dictionary with concrete value types, never `Any`. A list of records must be typed at least as `list[dict[str, TypedData]]`, with `TypedData` replaced by a declared concrete type, before validation into dataclasses.
- **Records are typed dataclasses, never tuples or dicts (PY-002, owner directive 2026-10-01).** No `-> tuple[int, list[str], int]`-style returns and no `dict[str, X]` records -- return a frozen `@dataclass`. `tuple[X, ...]` sequences are fine; dicts only at JSON/YAML/TOML boundaries typed with `JsonValue`/`YamlValue`/`TomlValue`. Parameters and annotated variables too (2026-10-02): no nested maps (`dict[str, dict[...]]`), no `dict[str, object]`/`Any` maps, no positional tuples (`list[tuple[str, str]]`) -- pass a dataclass (or a tuple of them); flat scalar maps, indexes of dataclasses and single-level parsed documents are fine. `python3 -m ci_lint selftest` enforces it as a ratchet (`ci_lint/tests/typed_records_baseline.json`): a module's count may only go down, new modules start at 0 -- lower the baseline when you convert one.
- **No capture-then-wait subprocess output (PY-003, owner directive 2026-10-01).** No `run(..., capture_output=True)`, `run(..., stdout=PIPE)`, `check_output`, `getoutput`. Iterating a `Popen` pipe while the child runs is fine. Outside ci_lint, the `running-process` package (`RunningProcess`, `subprocess_run`) is strongly encouraged; ci_lint itself (standard-library only) uses `ci_lint.proc.run_captured` (temporary files). Zero in ci_lint, enforced by the selftest; other repos use `ci-lint py lint` with a ratchet baseline.
- Treat a repo-specific deviation as either a documented exception or a finding requiring review; do not silently weaken the fleet policy.
- Use deterministic checks and GitHub run/job evidence before spending agent context on diagnosis. Label unclear expressions, scripts, and cache states as unknown.
- Do not add GitHub Actions workflow files unless the user specifically requests them.
- Before pushing to zackees/ci.yml, run `python3 -m ci_lint local-gate run` (stamps HEAD) -- the repository's `local-gate.toml` runs the selftest; install the pre-push hook once with `python3 -m ci_lint local-gate install-hook`.
- After changing `ci_lint` code, run `python3 -m ci_lint selftest` (or `uv run --no-project --with pyyaml python3 -m ci_lint selftest`) before reporting the change done -- this is the package's own `unittest` suite, and per zackees/zccache#1760 agents must be able to run it directly.
